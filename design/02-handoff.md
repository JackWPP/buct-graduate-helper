## 3. 必须实现的交互规则

1. **冷启动 < 2s 可读**：缓存优先渲染，分区骨架，首页首屏不阻塞在网络往返上。这是设计指标，不是纯性能问题。
2. **会话过期不白屏**：任意接口 302 → 记住当前页面 → 登录 → 回跳原位置。
3. **首页动态槽位**：今日课程之下的那一块随学期阶段切换（学期初 / 选课期 / 常规 / 期末 / 毕业期）。一屏覆盖全年级靠的是它，不是堆模块。
4. **课表**：左右滑动切周 + `‹ 第 10 周 ›` 箭头；周日无课自动隐藏该列；同一门课跨周同色；点击课程块**只弹层不跳页**。
5. **弹层 → 全屏详情**是两级：弹层回答"几点、在哪、谁上"，全屏页才给学分、周次、进度、提醒设置。
6. **选课**：每次提交都需要验证码，所以设计目标是**减少提交次数**——余量、冲突、门数超限必须在列表层前置，不能等提交失败才说。
7. **失败原因要归一化**：接口只返回中文 `msg`，客户端要映射成「余量满 / 时间冲突 / 不在选课时间 / 门数超限 / 已选过」五类再展示。
8. **抢课必须可见**：第几门、试了几次、为什么失败、下次何时重试；一键可停且停后不留后台任务；失败指数退避，不轰炸。
9. **颜色纪律**：红色只用于选课、退选、截止、退出登录四处。其余状态用字重与灰阶。

## 5. 三个开发前必须落实的前提

1. **第 1 周周一必须可配置**。接口给的是 `2026-08-31`，但每学期不同；写死会让整张课表的周次全错。
2. **节次时间读接口，不写常量**。当前是 1 节 08:00、6 节 13:30，改作息就全崩。
3. **校区映射要人工维护**。GMIS 地点只有"科303 / 教617"这种楼名，没有校区字段，需自建「楼 → 朝阳/海淀/昌平」映射表。

## 6. 已定 / 未定

**已定**
- 无既有设计稿，从零建立；拒绝使用校徽，标识自建（PRD 11.1）
- 首页由学期阶段驱动；服务 = 办事目录；我的 = 状态与记录
- 选课 = 方案页 + 课程池 + 抢课队列；抢课走「半自动 + 极速验证码」，不做全自动
- 推荐只按培养方案算结构，不做课程评价与社区
- 深色模式跟随系统，不给独立开关

**未定**
- 选课三屏的具体形态（等选课季前做，届时可测）
- 成绩、考试、空态、断网态
- 通知权限申请页（决定推送能不能用）
- 三个设置二级页

## 7. 一条设计债

课程块内目前只放课名 + 教室，因为 55px 宽放不下完整时间段（`09:45–12:15` 会折三行）。真实时间交给左侧时间轴，块内不重复。若后续块宽能加到 70px 以上，可考虑补上时间。
